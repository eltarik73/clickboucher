### Contained in C1-URGENCES

- **Decision**: the chef de chantier contains E09-02 here (commit « E09-02 »). The root cause, the
  publication rights of a shop (E09-01: anyone can become a butcher; a shop never validated can
  publish), stays with **C1-PUBLICATION**, which keeps the test below.
- **First barrier**: `POST /api/shop/offers` (`src/app/api/shop/offers/route.ts`) parses
  `butcherOfferSchema`, derived from `createOfferSchema` without `shopId`, `diffBanner`, `diffPopup`
  and every `banner*` / `popup*` field, in `.strict()` mode, and writes `diffBanner: false`,
  `diffPopup: false`. A body carrying any of those keys answers 400 `VALIDATION_ERROR` and writes
  nothing. `payer: "BUTCHER"`, `diffBanner: false` and `diffPopup: false` stay accepted as exact
  values because `ButcherOfferForm` sends them (`ButcherOfferForm.tsx:149-156`); any other value is
  refused. The route reads its body with `readJsonBody`. No butcher update handler exists in that
  family (`[offerId]/products` and `[offerId]/respond` write no diffusion field).
- **Second barrier**: `publicOfferWhere` (`src/lib/public-offers.ts`) diffuses the popup channel
  for platform offers only (`diffPopup: true, shopId: null`), so `listPopupOffers` ignores a shop
  row that already carries `diffPopup`, and such a row no longer counts as public through the popup
  on `/bons-plans` or its shop page. No home-page banner is read today: the `banner` channel has no
  caller, and the only banner is the shop page's own (`listShopOffers`), left unchanged.
- **Test kept**: `tests/integration/urgences/butcher-offer-diffusion.test.ts` (real handler, real
  PostgreSQL, butcher helper mocked): 14 refused bodies (each `banner*` / `popup*` key,
  `diffPopup: true`, `diffBanner: true`, another payer, another shop) answer 400 with no row; the
  form's body and a body without `payer` / `diff*` create a row with `diffPopup = false`,
  `diffBanner = false`; a shop row with `diffPopup` stored directly is absent from
  `listPopupOffers` and from `listPublicOffers`. 16 of its 18 cases fail on `f38c812`.
- **Production rows**: the read-only query of « Smallest containment » is for the owner to run; the
  second barrier already hides any row it returns from the pop-up.
