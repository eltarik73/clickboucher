# Skills Klik&Go — index

Relevé du 2026-11-14, complété le 2026-11-15 (skills de pureté du code). Une ligne par dossier de
`.claude/skills/` : quand le lire, et son statut.
Pour choisir les skills d'une tâche, partir de la table § 11 de
[`klikgo-programme`](klikgo-programme/SKILL.md). Les fiches de rôle des équipes sont dans
[`../agents/`](../agents/) (`klikgo-chef-de-chantier`, `klikgo-ingenieur-backend`,
`klikgo-ingenieur-front`, `klikgo-ingenieur-plateforme`, `klikgo-designer`, `klikgo-referenceur`,
`klikgo-testeur-recette`, `klikgo-relecteur`, `klikgo-auditeur-securite`).

**Précédence** : `CLAUDE.md` > `seo-anti-penalty` (indexation) > skills du programme > skills
préexistants. Un skill préexistant qui contredit `CLAUDE.md` ou un skill du programme ne fait pas
foi (exemples ci-dessous).

## Statuts

- **Vérifié 2026-11** : écrit ou réécrit par le programme, ancré dans le code, puis relu, et
  corrigé au besoin, par un vérificateur indépendant les 13 et 14 novembre 2026. Les limites
  restantes sont écrites dans chaque skill, souvent en « Points à arbitrer ». Ses chiffres sont
  une photographie : les relancer avant de les citer.
- **Contrôlé 2026-11-15** : skills de pureté du code, écrits ou réécrits les 14 et 15 novembre
  2026 à partir de sources publiques (licences et adaptations dans chaque `references/sources.md`),
  ancrés dans le code, puis contrôlés par un contrôleur indépendant sur `origin/main` `50f8886`
  (chemins, fonctions et commandes relus ; comptes remesurés là où le chantier C1-INVITES a changé
  le code). Leurs évaluations sont écrites hors dépôt mais n'ont pas encore été lancées contre une
  référence sans skill.
- **Préexistant, non revérifié** : antérieur au programme (souvent février–mai 2026, connaissances
  génériques) ; non relu ; à prendre avec prudence.

Le plugin `mattpocock-skills`, déclaré dans `.claude/settings.json` (`CLAUDE.md` « Agent skills »),
apporte `/code-review`, `/tdd`, `/diagnosing-bugs` et d'autres commandes qui recouvrent
`klikgo-review`, `test-discipline` et `fix-errors`. En cas de désaccord, `CLAUDE.md` et ces skills
du projet priment ; les écarts déjà relevés avec ce plugin (« confirmer les coutures avec
l'utilisateur », « relire la base dans un test est un anti-motif ») sont listés dans les
`references/sources.md` de `test-discipline` et `simplicity-refactoring`.
