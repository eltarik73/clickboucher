# Panne du 2026-11-05 : chiffres et erreurs à ne pas refaire

Source : audit multi-agents de novembre 2026 (I1 dans [sources.md](sources.md)), dont les fichiers
de travail ne sont pas versionnés. Les chiffres utiles sont recopiés ici, sauf ceux de consommation
du compte Vercel (registre privé du programme). « Mesuré » = relevé par
l'audit ; « déduit » = calcul fait à partir de ces relevés, à traiter comme une estimation. Les
temps CPU viennent d'un bac à sable local, pas de la production. Garde-fous revérifiés à `2364ef9`.

## Ce qui s'est passé

- Le site a répondu `402 DEPLOYMENT_DISABLED` : quota « Fluid Active CPU » dépassé, avec un trafic
  humain presque nul. La documentation Vercel associe ce code au dépassement des quotas (S24).
- Aucune alerte n'est partie pendant une semaine : tous les moniteurs (crons `seo-audit` et
  `bing-daily`, Sentry) tournaient **dans** le projet suspendu.
- Dernier commit avant la panne : 2026-06-12. Le site a donc consommé son quota sans aucun
  changement de code, 146 jours après le dernier déploiement.

Deux leçons chiffrées :

1. Le coût à chaud du code ne comptait presque pas (0,2 ms). Ce qui était facturé, c'était le
   **nombre d'exécutions**, chacune payant un démarrage à froid. Supprimer des exécutions rapporte
   cent fois plus qu'optimiser le code exécuté.
2. Les quotas d'invocations et de requêtes CDN étaient loin d'être atteints. **Le CPU actif est le
   compteur à surveiller.**

## Ce qui reste ouvert après les correctifs

- `/boutique/[slug]` est toujours rendu à chaque requête ([cache-cdn-isr.md](cache-cdn-isr.md) § 6).
- Le flux SSE du tableau de bord boucher se reconnecte toutes les 30 s tant qu'un onglet est ouvert,
  onglet caché compris (une exécution de middleware, une authentification et une requête Prisma à
  chaque reconnexion, plus la mémoire facturée pendant toute la connexion).
- Aucune revalidation à la demande n'est câblée ; les fenêtres ISR de 3 600 s restent le compromis.
- Règles de pare-feu et Bot Protection : à consigner dans le dépôt une fois publiées
  ([bots-firewall.md](bots-firewall.md) § 3) ; état réel : registre privé du programme.
- Budget et alertes de dépense : selon le plan ([points-a-arbitrer.md](points-a-arbitrer.md) § A et B).
- La part réelle de chaque route dans le CPU de production n'a jamais été mesurée
  ([mesure-et-capacite.md](mesure-et-capacite.md) § 2).
